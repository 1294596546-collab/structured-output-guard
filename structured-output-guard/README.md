# structured-output-guard（结构化输出兜底）

## 这是什么

一句话：**当模型的输出会被程序拿去用的时候，程序侧需要一层"就地规范化 + 留证据"。**

它不修模型，也不重试到成功为止。它做的事是：把不合规的输出改到合规，同时**把改了什么记下来**，
让"模型不听话"这件事变得可见、可统计、可追责。

它适用于 JSON、工具调用的参数、YAML——任何"结构化输出"。

## 六条规则

顺序不能换：后面的规则依赖前面的结果——**类型不对就没法判枚举，枚举没定就没法判能不能留空，
前面没做完就没法做动作分级。**

1. **解析与截取**——模型把结果裹在解释文字里，你得能切出来；切不出来时，**若启用追问分支就走追问，
   否则直接走全保守值**。
2. **类型与范围**——类型不对就归一，越界就拦，归一失败就留空并记一笔。
3. **枚举收敛到保守值**——不在你的取值集合里就落保守档；不许原样透传，也不许崩。
4. **允许留空还是必须非空**——允许留空的不许补占位符；必须非空的补占位并标记人工，但不许编内容。
5. **记录改动**——格式修正和业务降级分开记；"哪一项没取到"也要落进结果，不要只写日志。
6. **动作分级**——先分可逆与不可逆；只要出现业务降级、或标记了需要人工，
   **不可逆动作一律降级为可逆动作**（或转为人工执行）。

每条规则的失败形态、正例反例，见 [SKILL.md](SKILL.md)。

## 可选分支：追问策略

解析失败时，除了直接落保守值，还可以让模型重答一次。要用这个分支，先把四件事定清楚：

- **何时启用**：只在**解析失败**（切不出来、不是合法 JSON）时启用，而且你的场景**能容忍一次延迟**。
  超时、模型不可用属于不可恢复，追问没有意义。
- **追几次**：**一次**。第二次成功率下降很快，不如直接转人工。这个数字写死，别让用的人自己猜。
- **模板在哪**：在 [SKILL.md](SKILL.md) 的附录里，正文用"见附录"引用。模板里的字段名一律用占位符，
  保持业务无关。
- **追完还失败**：落**全保守值 + 转人工**，并**写一条 ERROR 级日志**。
  这一步必须写，否则"追问"就会变成无限重试的隐患。

追问由**程序的判据**触发，不能由模型自己说"我需要再问一次"；追问时要把上一轮的回答一起放回去，
否则模型很可能原样重复同一个答案。

示例里已经带了这个钩子（`retry_fn`），并用桩函数演示了两条路径，**不联网就能跑**。

## 怎么套到你自己的项目（三步）

**第一步，把你的字段列出来，分成四类。**

- 枚举型（有固定取值集合）：写清集合，并**指定哪个是保守值**；
- 数值型（有范围）：写清上下界；
- 自由文本型：标清"允许留空"还是"必须非空"；
- 引用型（必须能在别处查得到，比如单据号、用户号）：写清到哪查、查不到时怎么处理。
  示例里的 `order_id` 就是这一类——格式对还不够，**查不到一样不合法**。

**第二步，定保守值。**方法只有一句：

> 问自己"这个动作做错了能不能收回"。**收不回来的那一档就是保守档。**

注意方向在不同领域可能相反：客服的保守是"转人工"，医疗分诊的保守可能是"往严重里报"，
风控的保守是"拦下来"，而"要不要通知客户"的保守是**不发**。
**保守值必须你在自己的字段规格里填，skill 里不会替你写死。**

**第三步，加记录。**每处改动都记：规则编号、格式还是业务、哪个字段、改成了什么。
返回里同时给出"是否需要人看一眼"。

## 最小示例怎么跑

```bash
python examples/minimal_guard.py
```

跑完你会看到一张表：每个坏样本是被**哪一条规则**拦下的、改成了什么、是否需要人工。
最后会打印"六条规则各自被多少样本触发"，以及整体是否全部符合预期（不符合就退出码非 0）。

坏样本一条规则至少一个，另外有两个组合样本，用来验证规则**叠加**时的顺序；引用型字段
（`order_id`）也有两个样本，分别测"格式不对"和"格式对但查不到"。
表下面还有一段「可选分支」的演示：用桩函数走"追问后成功"和"追问后仍失败"两条路径，
顺带让你看到那条 ERROR 级日志长什么样。

想跑测试：

```bash
python tests/test_guard.py
```

## 什么时候不该用

这节是给你做判断的，不是给你念的。出现下面任何一条，就别上：

- 下游能容忍任意输入：输出只是给人看的文案，或者后面本来就有编辑/客服人工把关；
- 输出是确定性规则引擎或模板生成的，压根不会犯格式错；
- 你的字段全是自由文本，没有枚举、没有范围、没有引用完整性——六条里只有一两条对你有用；
- 场景里没有不可逆动作——第六条用不上（前五条仍然有用）；
- 就是自己跑一次看一次、人一直坐在旁边，那先别做，等它开始进自动化流程再说。

## 来源

这套规则来自一个真实项目：一个风电场的告警研判助手。摘要的六个字段要在界面上逐字展示、
还要驱动"要不要派人上塔检查"这种不可逆动作，所以程序侧必须兜住模型的输出。

那里实测到的三件事，也是这套规则的由来（前两条是**两批各三次**调用，不是同一批）：

- 补校验**之前**打了 3 次联网请求：**2 次模型返回的字段类型不对**（把列表当成字符串用）；
- 补上校验**之后**再打 3 次：**最终输出**全部合规；但**模型原始输出**里仍有 1 次类型错误，
  被程序当场改掉并记录；
- 有一条例外规则必须写进规格：**查不到的字段允许留空，绝对不许补"待确认"**——
  因为补了之后，下游会把"待确认"当成一个真实值。

完整的数值口径（含上面三次实测的原文）记在来源项目的 `开发记录.md` 第四部分。
如果这个 skill 是和来源项目放在同一个仓库里，翻那个文件即可；**单独上传时这段可以忽略**——
本 README 里已经带了关键数字。
