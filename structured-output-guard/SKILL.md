# 结构化输出兜底

## 什么时候用

同时满足下面两条以上就该用：

- 模型输出会被**程序**消费，而不是只给人看；
- 字段里有**枚举、数值范围、引用完整性**里任意一种（也就是"有东西能被违反"）；
- 输出会**驱动动作**，而且这个动作做错了收不回来。

反过来，如果输出只是给人读的文案、后面还有人工把关，或者输出本来就是确定性模板生成的，
那就不需要这一层。

## 六条规则

规则顺序不能换：**先解析，再类型与范围，再枚举，再判留空，最后动作分级**。
顺序错了会出现"先补了占位符，导致枚举判断失效"这类问题。

### 规则 1：解析与截取

模型经常把结构化内容裹在解释文字里（"好的，我看了下这个单子：{…}以上"）。
先把它截出来再解析；截不出来或解析失败，视为**不可恢复**，直接走全保守值。

*例*：客服消息 → 工单 JSON；数据库查询 → 结果集；模型回答 → 工具调用参数。
*反例*：不截取直接 `json.loads`，整句带解释的文本会让解析抛异常，程序崩在入口。

### 规则 2：类型与范围

字段类型必须符合你的声明。能归一就归一（`"1,234.5 元"` → `1234.5`，数组 → 拼接字符串），
归一失败或**越界**（超出你声明的上下界）就按"校验失败"处理：该留空的留空，并记一笔。

*例*：金额、数量、日期、时长；ID 长度与格式。
*反例*：把字符串金额直接拿去乘单价，结果变成 NaN，一路静默流到结算。

### 规则 3：枚举收敛到保守值

值不在你定义的取值集合里，就落到**保守值**，不许原样透传，也不许直接报错崩掉。

这里要区分两种情况：只是大小写或空格差异（`"High"` vs `"high"`）算**格式修正**；
语义上不认识（`"很急"`）算**业务降级**，两类的处理紧迫度不同。

*保守值怎么定*：问一句"这个动作做错了能不能收回"。收不回来的那一档就是保守档。
同一条枚举在不同领域方向可能相反——客服的保守是"转人工"，医疗分诊的保守可能是"往严重里报"，
风控的保守是"拦下来"。**所以保守值必须由使用者在自己的字段规格里填，不能写死在 skill 里。**

*反例*：枚举不认识就原样透传，下游按字符串匹配失败，走到默认分支，把本该人工审核的单子自动放行。

### 规则 4：区分"必须非空"和"允许留空"

- **允许留空**的字段：缺了就留空，**不许补任何占位符**——补了，下游会把占位符当成真实值。
- **必须非空**的字段：补一个显式占位符并标记需要人工，但**不许编内容**。

*例*：金额、日期这些"没有就是没有"的字段允许留空；分类、优先级这些必须非空。
*反例*：给"客户没说退货原因"补一个"待确认"，下游统计时把"待确认"当成一种退货原因统计进去。

### 规则 5：记录改动，并且分档

每个字段被改了什么都要记下来，并按两类归档：

- **格式修正**：归一化、大小写、去空格——无害，看日志就行；
- **业务降级**：枚举收敛、越界落空、动作降级——**必须有人看一眼**。

另外，"哪一项没取到"（外部接口失败、字段缺失）也要落进结果本身，不要只写在日志里。

*反例*：只打日志不返回，调用方拿到一个看起来完美的结果，不知道它已经被改过三处。

### 规则 6：动作分级

如果输出会驱动动作，先在字段规格里把动作分成**可逆**和**不可逆**两档。
只要出现业务降级、或者已经判定需要人工，**不可逆动作一律降级到可逆档**。

*例*：退款、发券、拦截发货、对外发消息属不可逆；仅回复话术、转人工、记备注属可逆。
*反例*：信息不全还是发了"已为您退款 129 元"的话术，钱出去了，人还得追。

## 可选分支：追问一次

解析或截取失败时，可以先让模型重答一次，而不是直接落保守值。要用这个分支，先回答六个问题：

1. **什么时候值得追问**：失败必须是**可恢复**的（解析不出、截取失败、返回空对象）。
   超时、模型不可用、报错退出属于不可恢复，追也没用，直接落保守值。
2. **追问几次**：**写死一次**。第二次成功率下降很快，不如直接转人工。使用者不得自行调整。
3. **模板在哪**：固定在附录，正文引用。模板里的字段名一律用占位符，保持业务无关。
4. **追完还失败怎么办**：落**全保守值 + 转人工**。这一步必须写，否则追问就成了无限重试的隐患。
5. **谁决定追问**：必须是**程序的判据**，不能是模型自己说"我需要再问一次"——
   判定权不能交给被检查的那一方。
6. **追问时带不带上一轮的回答**：要带。不带，模型很可能原样重复同一个答案，等于白问一轮。

### 附录：追问模板（业务无关）

```
你上一次的输出不符合要求：<把程序检查到的问题逐条列出来>。
请重新输出**一个**结构化结果，不要任何解释文字或代码块标记。
字段要求：<把字段名与取值集合换成占位符后列出来>。
确实无法确定的字段：允许留空的就留空；必须非空的填 <占位符>，不要编造内容。
```

## 返回约定

兜底函数的返回值建议固定成三样：

- `result`：规范化后的结果（类型与取值集合都已合规）；
- `issues`：逐条记录改了什么，每条含**规则编号、归档类别（格式/业务）、字段、改动详情**；
- `needs_human`：是否需要人看一眼（出现业务降级、或必须非空字段被补过 → 为真）。

## 附带交付物

用这套规则时，请把下面三样一起带上（见本目录）：

- `examples/bad_samples.json`：**一条规则至少一个坏样本**，每个样本标注"期望在第几条被拦"；
- `examples/minimal_guard.py`：最小可跑示例，跑一次会打印"样本 → 期望规则 → 实际触发 → 改了什么"；
- `tests/test_guard.py`：把上面的期望固化成断言，改规则时会被挡住。

追问分支在示例里用**钩子**实现：`normalize(raw, spec, retry_fn=None)`。
不传钩子＝不启用分支（解析失败直接落保守值）；传入一个 `f(raw, issues) -> str` 就会先追问一次。
示例用桩函数演示了两条路径（追问后成功、追问后仍失败），**不联网也能跑**。

## 边界

这是**最小演示与检查清单**，不是可直接上生产的库：它不做重试、不做限流、不做脱敏、不做审计留存。
生产上还要接你的日志与告警。
